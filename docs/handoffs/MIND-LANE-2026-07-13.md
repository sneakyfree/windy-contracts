# Windy Mind — doctrine retrofit punch list (first Class-C weave)

**What happened:** the doctrine lane retrofitted Windy Mind onto the Loom
(ADR-060 L3, first Class C — the cloud template). Mind's ops surface is a set
of real routes on `https://api.windymind.ai`, bound via `transport`. The
retrofit taught the Loom **remote transport**: cloud-class weaves now emit
`src/http.js`, a **Streamable HTTP MCP server at POST /mcp** so a hosted
agent (grandma's Fable running in the cloud) can reach the surface over the
internet — with **EPT passthrough**: the caller's own `Authorization` header
is forwarded verbatim to every backend call, so the shim holds no ambient
credentials for remote callers and Mind's EPT wall stays the single
authority. Proven end-to-end (remote MCP client → /mcp → mock backend saw
the caller's EPT on every call, including a query-arg route).

**Contract naming:** the manifest is `ops.mcp.v1`, NOT `control.mcp.v1`, on
purpose. Mind's product IS its inference API (`/v1/chat`); per ADR-060 §2 the
ops shim is a SEPARATE surface from the product API. The inference API is not
in this contract and never should be.

**What the retrofit EXPOSED — Mind can be OBSERVED but not HEALED.** All 5
implemented tools are reads (health, version, provider config, model list,
route explain). There is no remote way to change a provider key, read logs,
or redeploy — so when Mind is sick, an agent can see exactly what's wrong and
do nothing. ADR-060 §7 flagged this as **urgent**, doubly so because GitHub
Actions is billing-locked (no CI redeploy path). These are the gaps — NOT
advertised in the manifest (a knob that 404s mid-incident is worse than an
honest absence):

| Baseline knob | Status | What to build |
|---|---|---|
| `get_logs` | gap | Content-free recent logs endpoint (scrub prompts/completions — the privacy hard line). |
| `get_config` | gap | Read the effective runtime config (providers wired, routing policy), secrets redacted. |
| `set_<setting>` | gap | A **validated runtime-config** endpoint: change a provider key / routing rule WITHOUT a redeploy (today keys are env-at-deploy → any change = full redeploy). always_confirm; EPT OWNER band. |
| `apply_update` (redeploy) | gap | **The urgent one.** An SSH-free, health-gated redeploy hook so an agent can heal a sick Mind. Attested + last-known-good rollback. Class C "the ops plane lives outside the patient": this hook belongs in the ops/admin surface, not inside the api container it restarts. |
| `run_selftest` | gap | Actively round-trip a cheap model call through the broker and report pass/fail per provider. |
| `reconnect` / `restart_app` / safe-mode / `reset_to_defaults` | gap / unsupported | Decide per Mind's ops model — some may be genuinely `unsupported` (a stateless cloud service) and should be marked tri-state rather than built. |
| `check_for_update` | gap | Resolve current vs. the Steamroller's fleet version manifest (L2). |

## Other doctrine items for Mind

1. **`GET /tools` + `POST /invoke`** (§3.2): today the shim binds to bespoke
   routes (works). For the conformance LIVE gate and greenfield uniformity,
   add the uniform native shape when convenient — lower priority than the
   healing gaps.
2. **surfaces registration is via account-server, not surfaces.json** (§3.8):
   Mind is cloud; it is discovered by the account-server EPT query (L2), not
   the local file. No action in this repo beyond the manifest.
3. **Deploy the woven shim** behind Caddy at `api.windymind.ai/mcp` (or a
   dedicated `mcp.windymind.ai`) once the mutating knobs exist. Publishing /
   deploying is Grant-gated.

## Guardrail

Reads here are unauthenticated today (content-free). The moment mutating
knobs land, they MUST require EPT (OWNER band for config/redeploy) via Mind's
existing passport auth (`app/auth/`, the A3 revocation work is already in) —
the shim already forwards the caller's EPT; the api must enforce it.
