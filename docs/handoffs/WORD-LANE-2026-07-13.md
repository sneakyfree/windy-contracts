# Windy Word — doctrine retrofit punch list (from the first Gen-1 weave)

**What happened:** the doctrine lane retrofitted Windy Word onto the Loom
(ADR-060 L3, first Class-D reference). Word's :18765 surface is Gen-1 —
104 bespoke REST routes, not the uniform `POST /invoke`. Rather than rewrite
the hardened `main.js`, the Loom gained a per-tool **transport binding**
(the §4 escape hatch); Word's manifest at
`schema/fixtures/windy-word/control.mcp.v1.json` (canonical home:
`windy-pro/contracts/control.mcp.v1.json`) binds each tool to its real
route. The generated packet was proven end-to-end: an MCP client called it,
and GET/query, POST/body, and POST/no-body all dispatched to the right
routes with the bearer token attached.

**What the retrofit EXPOSED — Word is rich in feature tools but poor in the
healing baseline.** 5 of the 13 baseline knobs are live; 8 are gaps. These
are NOT advertised in the manifest (a packet that offers `apply_update` and
404s mid-incident is worse than one that omits it) — they are this punch
list. Matches ADR-060 §7's Word row exactly.

## The 8 baseline gaps (owner: the windy-pro/Word lane)

| Knob | Status | What to build (small, safe, read-mostly first) |
|---|---|---|
| `get_logs` | gap | A route returning recent app logs, **scrubbed of secrets/content**. Read-only; lowest risk; do first. |
| `run_selftest` | gap | Actively exercise the core path (transcribe a bundled test clip → verify text out), pass/fail per stage. Distinct from `/doctor/diagnose` (which is `get_health`). |
| `get_capabilities` | gap | Tri-state per FEATURE (recording, paste, tts, clone, translate…) — probed, not assumed. Note: `/install/capabilities` is about installable deps, a different thing. |
| `reconnect` | gap | Re-establish the Python engine connection without a full restart. |
| `enter_safe_mode` / `exit_safe_mode` | gap | Minimal known-good overlay (default engine/devices, hands off). §7 flagged this. |
| `apply_update` | gap | The real update knob — attested artifact + **last-known-good rollback**. Only `check_for_update` exists today. always_confirm tier. |
| `reset_to_defaults` | gap | Factory-reset settings, **preserving** user transcripts/clones. always_confirm tier. |

## Other doctrine items for Word (beyond the baseline)

1. **`GET /tools` + `POST /invoke`** (ADR-060 §3.2): Word serves 104 bespoke
   routes but not the uniform native-transport shape. The woven packet works
   over the bespoke routes today (transport bindings), but the conformance
   driver's LIVE gate needs `GET /tools` (serve the manifest's tool list).
   Add it — it's a small read-only route.
2. **The "doctor is not in the patient"** (§3.6): the control server lives
   inside Electron and dies with the app. Needs the out-of-process
   supervisor + OS resurrection (Windy Talk's supervisor.ts +
   resurrection/installer.ts are the reference). This is the biggest item
   and the most valuable — it's what makes `restart_app` work when the app
   is already dead.
3. **Full coverage-parity enumeration** (§1 coverage law): this first
   manifest is the baseline + proven sound/settings tools (13). Word's other
   ~90 routes (archive, clones, paste strategies, tts, translate, window,
   account/billing, install…) must be enumerated into the manifest so the
   generated packet reaches parity with — then replaces — the hand-written
   windy-word-mcp@1.11.0. Derive them from the existing packet's tool
   definitions (they already carry descriptions + schemas + route mappings);
   this is mechanical, not creative. Do it in reviewable batches by category.
4. **`surfaces.json` registration** (§3.8) and **`contracts/weave.json`**
   (per `schema/weave-config.v1.schema.json`) so Word is discoverable and
   weavable from its own repo.
5. **Retire the hand-written packet** only when the generated one reaches
   full parity AND passes conformance — then `windy-word-mcp` publishes from
   the Loom. Publishing stays Grant-gated.

## Guardrails

`main.js` is the most dangerous file in the ecosystem (its paste path took
down Grant's terminals twice on 2026-07-12 — see windy-pro CLAUDE.md). Every
new baseline route is an ADDITIVE handler; touch nothing in the
recording/paste/Wayland/focus paths. Feature branches + PRs; local
`npm test` + `npx jest` green. The token wall (control-auth.js, #231) already
guards all these routes.
